# Open banking / open finance APIs usable by a small OSS digital bank for REAL production data (state as of 2026-11-04)

Legend used throughout: **[NO-CRED]** = callable with zero credentials; **[FREE-SIGNUP]** = free account/API key, no regulatory licence; **[LICENSED]** = needs regulated TPP status (FCA/NCA AISP registration, eIDAS QWAC/QSEAL or OBIE OBWAC/OBSeal) or a contract with a licensed aggregator. "LIVE-VERIFIED" means I fetched the endpoint with curl from this session on 2026-11-04 and recorded the HTTP status + response excerpt. All fetches used `Accept: application/prs.openbanking.opendata.v2.2+json, application/json` unless noted.

## Key Question 1: UK Open Banking "Open Data" APIs (OBIE Open Data v2.x) — which bank endpoints are still live with NO authentication in 2026, and is there a directory?

### Takeaway
Yes — the OBIE Open Data v2.2 endpoints (ATMs, Branches, PCA, BCA, Commercial Credit Cards, SME loans, FCA service metrics) are still live in Nov 2026 at most CMA9-era banks and need **no credentials at all**; I live-verified 80+ URLs. The authoritative directory is OBL's `participant_store.json` (20 providers, last updated 2019 but still accurate for ~16 of them); Monzo and Starling do NOT publish Open Data endpoints, Santander is behind an Incapsula bot wall, Barclays only publishes ATMs/Branches.

### Cited Findings
- **Directory**: OBL's "Open Data API Dashboard" (Confluence, page last updated 2023-04-20) lists per-provider endpoints and says users must accept the OBL Terms and the Open Data Licence before use; it links a machine-readable list at `https://github.com/OpenBankingUK/opendata-api-spec-compiled/blob/master/participant_store.json` — [Open Data API Dashboard](https://openbanking.atlassian.net/wiki/spaces/DZ/pages/1165263140/Open+Data+API+Dashboard)

### Inferences
- The OBIE Open Data set is the only UK bank data a small OSS project can consume in production today with literally nothing: no key, no registration, no mTLS. It is reference/product data (products, rates, fees, overdraft EARs, ATM/branch locations, service quality), not customer accounts.
- Because every live provider still serves v2.2 (and v2.3/v2.4 paths 404), the project should code against the v2.2 schema and treat the v2.4 spec as documentation only.
- The participant store's 2019 timestamp means treat it as a seed list: Barclays products, Coutts, Adam & Co, Esme, Santander (bot wall) and CYBG metrics are stale/unusable, and Nationwide's host changed to `openapi.nationwide.co.uk`.
- Lack of published rate limits plus `max-age=28800` caching suggests fetching each endpoint at most a few times per day and caching locally.

### Gaps
- Could not read the Open Licence PDF itself (only the web summary that it is MIT-style); exact attribution wording for *data* reuse should be checked in the PDF linked from the Open Licence page.
- Santander Open Data could not be verified (Incapsula challenge); its developer portal (`developer.santander.co.uk/sanuk/external/product/open-data`) also returned 403 to curl/WebFetch.
- Nationwide `branches` returned 403 (reason unknown); Barclays PCA/BCA/SME/CCC 404 (possibly withdrawn).
- No bank publishes numeric rate limits for Open Data; none found in docs.

### Inferences
- For FX in a demo bank, Frankfurter (self-hostable, MIT-style OSS) or the ECB XML feed is the simplest; Bank of Israel PublicApi gives ILS representative rates and the policy rate with no key, which is ideal for an Israel-flavoured demo.
- BoE and Fed data are CSV-only; a small parser is needed. FiscalData is the only US-government JSON API with zero auth.
- Because the Bank of Israel website (boi.org.il HTML pages) sits behind Radware bot protection while `boi.org.il/PublicApi/*` and `edge.boi.gov.il` do not, server-side calls should target only those two hosts.

### Gaps
- Numeric rate limits are undocumented for ECB, BoI, BoE, Fed, FiscalData and Frankfurter; FRED's limit (commonly cited as 120 req/min) was not found on the page fetched, so it is unverified.
- Could not read BoI's official English API user guide (Radware block); timing of daily rate publication conflicts between sources (≈14:00 vs ≈15:45 Israel time).
- SWIFT gpi onboarding fees/eligibility not found.

## Key Question 3: Free-tier account aggregation with REAL production bank connections (GoCardless BAD, Enable Banking, Salt Edge, Tink, Plaid, TrueLayer, Yapily) — can an individual developer connect their own real account for free, and where?

### Takeaway
The free self-serve routes have narrowed sharply: **GoCardless Bank Account Data is closed to new signups** (official page, LIVE-VERIFIED), leaving **Enable Banking's free "restricted production" mode (own pre-linked accounts, EU/UK ~29 countries)** as the main zero-cost path to real PSD2 data; Plaid offers a free Trial (10 production Items) only for new US/CA accounts; Salt Edge advertises a time-limited free Basic tier; Tink, TrueLayer and Yapily are sales-gated for production. None of them cover Israel.

### Cited Findings
- **GoCardless Bank Account Data (ex-Nordigen)** — official page `https://bankaccountdata.gocardless.com/new-signups-disabled`: "New signups for Bank Account Data are currently disabled." (no date given) — [GoCardless: new signups disabled](https://bankaccountdata.gocardless.com/new-signups-disabled). Actual Budget docs: "from July 2025 onwards, GoCardless has stopped accepting new Bank Account Data accounts"; existing users' accounts continue to work — [Actual Budget docs](https://actualbudget.org/docs/advanced/bank-sync/gocardless/). ## Key Question 4: Israel — Bank of Israel open banking standard, who can access it, aggregator coverage, and public no-auth Israeli financial data

### Takeaway
Israel's open banking runs on the Berlin Group standard as adapted by the Bank of Israel (Proper Conduct of Banking Business Directive 368) and extended to payment companies by an ISA directive finalised 7 June 2026; only entities licensed/authorised under the Financial Information Service Law 2021 (ISA licence) or the Payment Services and Payment Initiation Law 2023 may access it — **[LICENSED]**, no hobbyist route. No European aggregator surveyed lists Israeli banks. Free public data exists from the Bank of Israel (PublicApi + SDMX, no auth) and TASE DataHub (free key for 4 basic products).

### Cited Findings
- Bank of Israel press release: open banking "will enable third parties to receive a customer's financial information from the banks with the customer's consent"; the standard covers a data dictionary, API services, system rules, information security and privacy — [BoI press release](https://boi.org.il/en/communication-and-publications/press-releases/the-banking-supervision-department-is-leading-the-regulation-of-an-open-banking-standard-in-israel/). A separate BoI release states third parties must be licensed by the regulator before accessing a customer's account — [BoI guidelines press release](https://boi.org.il/en/communication-and-publications/press-releases/the-bank-of-israel-publishes-guidelines-for-the-banks-and-credit-card-companies-for-implementation-of-the-open-banking-standard-in-israel/) (both BoI HTML pages are behind a Radware bot-check; text from search index).
- ISA draft directive for payment companies (published 2026-01-27): standard is "the Berlin Group Standard, as adopted and adapted for the Israeli market by the Bank of Israel"; Appendix A refers to BoI Proper Conduct of Banking Business Directive No. 368 "Open Banking in Israel"; access is for "Third-Party Providers" = financial information service providers and payment initiators; obligations enter into force 2026-06-06, advanced payment initiation 2026-12-06 — [Herzog Fox & Neeman, 2026-02-04](https://herzoglaw.co.il/en/?p=74131)
- Final ISA directive published 2026-06-07: Annex A references the Berlin Group Standard "as published by the Bank of Israel on its website"; obligations rest on the Financial Information Service Law 2021 (FIS Law) and the Regulation of Payment Services and Payment Initiation Law 2023; open banking obligations apply three years from the date a payment company receives its licence; directive PDF (Hebrew) at `https://www.new.isa.gov.il/images/Fittings/isa/asset_library_pic/al_lobby/al_lobby-63a2db729e575/open_banking_forPSP.pdf` — [Herzog Fox & Neeman, 2026-06-18](https://herzoglaw.co.il/en/news-and-insights/israel-securities-authority-publishes-directive-for-payment-companies-regarding-the-implementation-of-an-open-banking-standard/)
- FIS Law 2021: requires large financial institutions to share consumer data with licensed third parties; information baskets = bank/checking accounts, credit cards, debit cards, securities, savings; licence from the ISA requires a company (control/management in Israel or ability to comply from abroad), technology/security, business plan, insurance, minimum equity and collateral; permitted uses: collection, consulting, brokerage, cost comparison — [Gornitzky: The Open Banking Reform (2022-10-19)](https://www.gornitzky.com/the-open-banking-reform/)
- FIS Law came into effect June 2022; inception for licensed credit providers postponed to 2025-05-14 and for some smaller credit providers until 2027-05-28; a bill published 2026-05-11 would let foreign providers get a tailored licence — [Barnea Jaffa Lande](https://barlaw.co.il/practice_areas/regulation/client_updates/legislative-updates-for-regulated-financial-service-providers-inception-of-the-financial-information-service-law); [Herzog: foreign providers bill](https://herzoglaw.co.il/en/news-and-insights/proposed-government-bill-allowing-foreign-service-providers-to-obtain-a-tailored-license-to-operate-in-israel/)
- Aggregator coverage: Open Banking Tracker's Bank of Israel entry lists no API products — [openbankingtracker: Bank of Israel](https://openbankingtracker.com/provider/bank-of-israel); a community skill notes "there is no single unified API across Israeli banks and that some integrations rely on scraping" — [skills.sh israeli-bank-connector](https://skills.sh/skills-il/tax-and-finance/israeli-bank-connector). ## Key Question 6: Standards references and how production access is obtained (OBUK v4.0, Berlin Group 1.3.x / openFinance, FAPI, consent flows, AISP registration / agent model)

### Takeaway

- Israel: Berlin Group standard as adapted by the Bank of Israel (Directive 368); access only for licensed financial information service providers / payment initiators — [Herzog 2026-06-18](https://herzoglaw.co.il/en/news-and-insights/israel-securities-authority-publishes-directive-for-payment-companies-regarding-the-implementation-of-an-open-banking-standard/)

### Inferences
- Realistic tiering for the project: Tier 0 (no creds) = OBIE Open Data + central-bank data; Tier 1 (free signup) = Enable Banking restricted production for the developer's own EU/UK accounts, Starling/Monzo personal tokens for own accounts, Plaid Trial for US, FRED/OXR/TASE keys; Tier 2 (licensed) = direct OBUK v4.0.1 / Berlin Group 1.3.16 integration with OBWAC/OBSeal or QWAC/QSEAL, or becoming an FCA-registered agent of a licensed AISP.
- A "regulatory sandbox" is not a shortcut to production data: bank sandboxes (e.g. OBP, bank developer portals) return synthetic data; the FCA sandbox is a supervised testing programme, not an API credential (no source consulted on FCA sandbox specifics — see Gaps).

### Gaps
- Did not find any 2026 source on FAPI 2.0 adoption by OBL or Berlin Group; treat FAPI 1.0 Advanced (UK) and Berlin Group's own OAuth2/eIDAS profile (EU) as current.
- FCA regulatory sandbox / "agent of AISP" cost and timeline figures are from vendor blogs (2020); the FCA's current Perimeter Guidance was not fetched.
- Starling's own developer terms (free personal access) could not be read from its JS-only portal.
